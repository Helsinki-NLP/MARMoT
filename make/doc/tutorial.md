# Tutorial: Running multilingual experiments like `models/hpo`

This tutorial walks through the experiment makefiles in [`models/hpo`](../../models/hpo). Those experiments train large multilingual machine translation models with MAMMOTH: a set of "pivot-centric" translation tasks towards one or more pivot languages (e.g. English-centric, English/French-centric, ...), optional monolingual *denoising* tasks, and *zero-shot* tasks that are only evaluated, never trained. The directory contains many variants of the same setup (different model sizes, layer counts and parameter-sharing patterns) produced by the HPO search.

The examples assume the [environment](env.md), [data](data.md) and [vocabularies](../config/vocab.mk) are set up on your host. Everything below is explained with the models in `models/hpo`; the same patterns apply to any experiment based on the [makefiles](../README.md).

## The anatomy of an experiment makefile

Let's look at the key parts of [`models/hpo/base-2p+d-Aenc-Ldec-640k/Makefile`](../../models/hpo/base-2p+d-Aenc-Ldec-640k/Makefile) (English/French-centric, denoising, fully-shared encoder, language-specific decoder):

### 1. Load the environment early

```make
include ../../../make/env.mk
```

`env.mk` loads the host-specific defaults (partitions, `MAX_GPUS_PER_NODE`, ...) and the utility functions from `utilities.mk`. Bringing it in *before* defining tasks is only needed if you use the makefile utilities (like `rotating_gpu_assignment` below); the full `marmot.mk` is included at the end of the file.

### 2. Define the task list programmatically

Instead of writing several hundred language pairs by hand, the task IDs are generated with `foreach` over a list of languages:

```make
LANGUAGES := 	bos bul cat ces dan deu ell eng \
		est eus fin fra gle glg hrv hun \
		isl ita kat lav lit mkd mlt nld \
		nno nob pol por ron slk slv spa \
		sqi srp_Cyrl swe tur ukr

## translation tasks towards the pivot languages (eng, fra, ...)
DOCMT_PIVOT_LANGS := eng fra
DOCMT_TASK_IDS    := $(sort $(foreach p,${DOCMT_PIVOT_LANGS},$(foreach l,$(filter-out $p,${LANGUAGES}),mt_$l-$p mt_$p-$l)))
DOCMT_TRANSFORMS  := $(foreach l,${DOCMT_TASK_IDS},filtertoolong)

## denoising tasks (one per language)
DENOISE_TASK_IDS   := $(foreach l,${LANGUAGES},denoise_$l-$l)
DENOISE_TRANSFORMS := $(foreach l,${DENOISE_TASK_IDS},denoising,filtertoolong)
```

Note the task ID prefixes (`mt_`, `denoise_`): `TASK_IDS` is a free-form list, so the same language pair can appear in several tasks with different IDs (and different data/transforms). The prefix also defines the *task type* (`{task}`), used for encoder/decoder sharing patterns in some configs.

Combining everything into the final lists:

```make
TASK_IDS        := ${DOCMT_TASK_IDS} ${DENOISE_TASK_IDS}
TASK_TRANSFORMS := ${DOCMT_TRANSFORMS} ${DENOISE_TRANSFORMS}
TASK_GPUS       := ${DOCMT_GPUS} ${DENOISE_GPUS}
```

### 3. Assign tasks to GPUs

The GPU assignment is generated by the `rotating_gpu_assignment` helper: `$(call rotating_gpu_assignment,<start_node>,<nr_nodes>,<nr_tasks>)`:

```make
DOCMT_GPUS   := $(call rotating_gpu_assignment,0,9,$(words ${DOCMT_TASK_IDS}))
DENOISE_GPUS := $(call rotating_gpu_assignment,9,1,$(words ${DENOISE_TASK_IDS}))
```

This places one task per GPU, rotating over node ranks 0-8 for the translation tasks and then packing all denoising tasks onto node 9 (multiple tasks per GPU). The makefiles turn these assignments into the SLURM node/GPU requests automatically.

#### Zero-shot tasks (evaluated but not trained)

The `base-1p+d-Aenc-Ldec-320k` variant shows the standard zero-shot trick: include the tasks with weight 0 so they appear in the config (and can be evaluated) but are never sampled during training.

```make
ZEROSHOT_TASK_IDS  := $(foreach l,${ZEROSHOT_TASKS},zero_$l)
ZEROSHOT_TRANSFORMS := $(foreach l,${ZEROSHOT_TASK_IDS},filtertoolong)
ZEROSHOT_WEIGHTS   := $(foreach l,${ZEROSHOT_TASK_IDS},0)
ZEROSHOT_GPUS      := $(call rotating_gpu_assignment,0,5,$(words ${ZEROSHOT_TASK_IDS}))
```

Because `TASK_WEIGHTS` only lists values for the first (zero-shot) tasks, all following tasks automatically get the default weight 1.0.

### 4. Data, vocabularies and training parameters

```make
TRAINDATA := multisynt/train/len1024        # <-- under ${DATA_DIR}
VOCAB     := tatoeba_hplt_multisynt         # <-- under ${PROJECT_DIR}/tokenizer

BATCH_SIZE       := 32768
GRADIENT_ACCUM   := 10
KEEP_CHECKPOINTS := 10

SLURM_MAX_GPU_TIME := 24:00:00
```

The model-name suffix `640k` refers to the approximate batch size in tokens per gradient update: `BATCH_SIZE * GRADIENT_ACCUM` = `32768 * 20` ≈ 640k. `VALID_FREQ`/`SAVE_FREQ`/`REPORT_FREQ` (2500/2500/500 by default) control the frequency of validation, checkpointing and reporting.

### 5. Include the full makefile suite

```make
include ../../../make/marmot.mk
```

Everything must be defined before this line; after it, all targets and generated configurations are available.

## Variants in `models/hpo`

### Model sizes

`MODEL_ARCHITECTURE` selects one of the presets in [config.mk](../config.mk) (`transformer-small`, `transformer-base`, `transformer-big`, `transformer-xl`, ...). The directories named `small-*`, `base-*`, `big-*`, `xl-*` (and `Enc*/Dec*` variants, which set the architecture explicitly instead of using a preset) were produced that way.

### Parameter sharing

The sharing pattern is controlled by `TASK_ENCODERS` / `TASK_DECODERS` (or `DEFAULT_ENCODER` / `DEFAULT_DECODER`):

```make
# language-specific encoder+decoder (default): nothing to set
# fully shared encoder, language-specific decoders:
DEFAULT_ENCODER := "all"

# encoder shared per language group + fully shared, e.g. the 'GAenc' variants:
ENCODER     := "{langgroup}","all"
ENCODER_LAYERS := 3,3
```

### Explicit architectures

Instead of a preset, layer counts, dimension and heads can be set directly:

```make
ENCODER_LAYERS  := 6,6        # 6 layers per language group + 6 fully shared
DECODER_LAYERS  := 3
MODEL_DIMENSION := 768
TRF_HEADS       := 4
```

### Alternative transformer backend

`XTbaseD1K-2p-GAenc-Ldec-320k` additionally sets the backend before including the environment (the LUMI env uses it to pick the right MAMMOTH installation):

```make
TRANSFORMER_BACKEND := x-transformers
```

## Working with an experiment

From within the experiment directory:

```bash
make info                     # how many tasks did we generate?
make task-info                # task -> GPU assignment table
make train-slurm              # generate config + slurm script without submitting
make train                    # generate everything and submit the training job
```

You can inspect the generated configuration in `mammoth/train.yaml` and the SLURM script in `mammoth/train.slurm` before starting a (possibly very long) run.

While training runs, monitor it with:

```bash
make print-validation-scores          # BLEU tables per task and validation step
make PRINT_METRIC=perplexity PRINT_LAST=3 print-validation-scores
make print-validation-diffs
```

Evaluate the model on the default test set (or a specific one) and compare with the OPUS-MT dashboard:

```bash
make eval                                 # one job, all tasks
make eval/newstest2013                    # evaluate on a specific test set
make print-evaluation-scores
make print-eval-score-comparison          # compare to best OPUS-MT scores
```

### Zero-shot evaluation

The hpo makefiles define a pattern rule for evaluating the zero-shot language pairs:

```make
.PHONY: %.zero-shot
%.zero-shot:
	@${MAKE} -s $(basename $@) \
		SLURM_GPU_PARTITION=dev-g \
		EVAL_TASKS_WALLTIME=15:00 \
		TASKS="por-swe ces-ukr" \
		TASK_IDS="mt_por-swe mt_ces-ukr"
```

which switches the task list at evaluation time. Use it like this:

```bash
make eval.zero-shot
```

(Only for short evaluation jobs; `TASKS`/`TASK_IDS` here replace the training tasks just for the evaluation targets.)

## Collecting statistics for many models

The top-level [`models/hpo/Makefile`](../../models/hpo/Makefile) iterates over all model directories and aggregates their statistics (this is what fills the `stats/` directories and `models.txt` in the repository):

```bash
make -C models/hpo all          # write stats/*.txt for every model and commit them
make -C models/hpo monitor      # same, but re-run every hour
```

It runs `print-train-stats`, `print-valid-stats` and `print-eval-stats` inside each model directory, i.e. the same reporting targets described in the [README](../README.md). If the generated configuration ever changes (e.g. after a makefile update), the config files can be regenerated in all models at once with:

```bash
make -C models/hpo refresh-configfiles
```

# models: the MAMMOTH experiment registry

This directory records the model configurations that have been trained (or are
being trained) in the MARMoT project, together with their validation and
evaluation scores. The scores are what the [training dashboard](../dashboard)
plots.

Each experiment is a directory containing:
* a `Makefile` that defines the experiment (tasks, training data, vocabulary,
  parameter sharing, ...) and ends by including the shared framework,
  `include ../../../make/marmot.mk`; and
* a `mammoth/` directory with the generated and committed artifacts, notably
  `train.yaml` (the MAMMOTH configuration), `stats/` (score tables), and the
  training/evaluation logs.

Some model directories only carry the committed `mammoth/` artifacts and no
`Makefile`; the configuration can be read from `mammoth/train.yaml`.

To (re)produce an experiment, run the usual `make/` targets inside its
directory, e.g.:

```bash
cd models/hpo/base-1p+d-Aenc-Ldec-320k
make train          # submit training
make print-eval-stats  # write score tables into mammoth/stats/
```

See the [`make/` documentation](../make/README.md) and the
[tutorial](../make/doc/tutorial.md) for the full workflow.

## Experiment groups

| Directory | Contents |
| --- | --- |
| [`hpo/`](hpo/README.md) | The main hyperparameter search: model sizes (`small`/`base`/`big`/`xl`), numbers of pivot languages (`1p`–`4p`), denoising (`+d`), different parameter sharing schemes (`L`/`G`/`A` encoders and decoders), and batch sizes. See the naming conventions in the README. |
| [`hpo-xtransformers/`](hpo-xtransformers/README.md) | Extended-transformer variants: sentence-level (`sentmt`) and document-level (`docmt`) MT, denoising, next-sentence prediction (`predict`), and FLAN instruction data, with several encoder-sharing schemes (`sharedenc`, `halfsharedenc`, `LGAenc`). |
| [`hpo-batchsize/`](hpo-batchsize/README.md) | Ablations of batch size and gradient accumulation for the English-centric base doc-level model. |
| [`multitask/`](multitask/models.txt) | Multitask models combining several objectives, marked in the name by `+si` (simplification), `+dm` (document-level MT), `+sum` (summarisation), `+dn` (denoising) and `+pp` (text prediction). |
| [`testruns/`](testruns/README.md) | Small debug and validation runs, e.g. language-token experiments and `docmt-validzeroshot`. |

## Naming conventions

Model names encode the setup as `<model>-<tasks>-<enc>-<dec>-<batch>`:

* **model**: `tiny`, `small`, `base`, `big`, `xl` (transformer size);
* **tasks**: `1p`/`2p`/`3p`/`4p` = number of pivot languages
  (English-centric, English/French-, English/French/Spanish-,
  English/French/Spanish/German-centric), `d` = monolingual denoising;
* **enc**/*dec*: parameter sharing of encoder/decoder — `L` = language-specific,
  `G` = shared across language groups, `A` = shared across all languages
  (combinations like `GA`, `LA`, `LGA` are possible);
* **batch**: approximate number of tokens used for one gradient update
  (batch size × accumulation, e.g. `320k`).

The group READMEs add the vocabulary used for the newer
`sentmt`/`docmt`/`predict`/`flan` experiments (see
[`hpo-xtransformers/README.md`](hpo-xtransformers/README.md)).

## Statistics and score files

The `stats/` directory of a model holds the text tables that the dashboard
reads:

* `stats/valid-scores-bleu.txt`, `stats/valid-scores-chrf.txt`,
  `stats/valid-scores-ppl.txt` — validation scores per task and checkpoint;
* `stats/train-progress.txt` — training progress, used to plot scores against
  consumed tokens or training time.

These files are produced by the reporting targets of the `make/` framework
(`make print-train-stats`, `make print-valid-stats`, `make print-eval-stats`)
and committed to the repository.

### Updating the statistics

The makefiles in this directory automate the collection and commit of the score
tables. Each experiment group has a makefile that recurses into its model
directories:

```bash
cd models/hpo
make all        # update all stats, regenerate models.txt, commit and push
make monitor    # do the above every hour
```

Run at the top level, [`models/Makefile`](Makefile) updates every group,
regenerates the top-level `models.txt` (all model directories), and commits the
result:

```bash
cd models
make
```

The `experiments.txt` file (the known experiment groups, i.e. the directories
containing a `models.txt`) is regenerated by the `experiments.txt` target.
Both `models.txt` and `experiments.txt` are read by the dashboard.
